1. Contexto y Objetivo
La app FLUJO_CAJA provee analisis historico de cartolas bancarias (Tab 1). Este modulo agrega Tab 2 con
proyeccion de caja a 30/60/90 dias integrando multiples fuentes de datos sin afectar el codigo existente.
Principio fundamental: Tab 1 no se toca. Todo el codigo nuevo va en archivos separados.

3. Proyecciones Versionadas (CRITICO — nuevo en v2)
PUNTO MAS IMPORTANTE DEL DISENO — sin esto no hay trazabilidad ni mejora del modelo
Problema sin versionado:
Sin snapshot historico cada recalculo sobreescribe la proyeccion anterior. No es posible responder: que
proyectabamos para marzo hace 4 semanas y que paso realmente?
Solucion — concepto de snapshot:
Cada proyeccion generada se guarda con fecha y version. El usuario puede comparar snapshots anteriores contra el
flujo historico real (Tab 1), midiendo calidad del modelo y desviaciones.
Esto permite:
• Comparar proyectado vs real por categoria y periodo
• Detectar donde el modelo consistentemente se equivoca
• Dar trazabilidad al cliente — puede ver la evolucion de sus proyecciones
• Medir la calidad del servicio de Kappo en el tiempo
Estructura de tablas para versionado:
proyeccion_snapshots ® cabecera de cada proyeccion (fecha, version, etiqueta)
proyeccion_lineas ® detalle de cada linea con tipo_confianza y categoria
4. Modulos del Sistema
Modulo 1 — Facturas ERP (Kame)
• Kame API REST — cliente debe contratar acceso API (client_id + client_secret)
• Make extrae diariamente facturas pendientes de los ultimos 90 dias
• NUEVO v2: Streamlit persiste las facturas en BD antes de leerlas — el sheet es temporal
• tipo_confianza = real si tiene fecha_vencimiento directa / estimado si se calcula
Endpoints Kame necesarios:
GET /api/v1/documentos/ventas -> facturas por cobrar clientes
GET /api/v1/documentos/compras -> facturas por pagar proveedores
Confirmar con Kame: valor estado factura pagada, si entrega fecha_vencimiento directa, si hay paginacion.
Modulo 2 — Importaciones
NUEVO v2: Fechas de impacto en caja definidas explicitamente por evento
Cada evento de una importacion tiene su propia fecha de impacto en caja:
Evento Fecha de impacto en caja Categoria tipo_confianza
Pago a proveedor extranjero fecha_pago_proveedor PROVEEDORES EXTRANJmERanOuSal
Gastos aduana / flete / seguro eta_real o eta_estimada GASTOS IMPORTACION estimado
IVA diferido importacion dia 12 mes siguiente a eta IVA IMPORTACION estimado
Si fecha_pago_proveedor no esta ingresada se usa eta_estimada y tipo_confianza = estimado. La app debe advertir
visualmente cuando una fecha de impacto es estimada.
Modulo 3 — Egresos Parametricos
Logica de desfase fiscal: impuestos del mes M se pagan el dia 12 del mes M+1
IVA_debito(M) = suma monto_iva facturas_ventas mes M
IVA_credito(M) = suma monto_iva facturas_compras mes M
IVA_neto(M) = IVA_debito - IVA_credito (negativo = remanente acumulable)
PPM(M) = suma monto_neto ventas mes M x tasa_ppm_usuario
fecha_pago = dia 12 mes M+1 -> tipo_confianza = estimado
Parametro Tipo Default Validacion
tasa_ppm % numerico Sin default WARNING obligatorio — bloquea proyeccion si no esta
tasa_retencion_honorarios % numerico 10.75% Solo si paga honorarios
dia_pago_impuestos entero 1-28 12 Editable por usuario
dia_pago_remuneraciones entero 1-28 ultimo habil Editable por usuario
dia_pago_imposiciones entero 1-28 10 Editable por usuario

6. Tipo de Confianza por Linea (nuevo en v2)
Cada linea de la proyeccion lleva indicador visual de confianza
tipo_confianza Significado Origen tipico Color UI
real Dato confirmado del ERP o cartola Kame API con fecha vencimiento directaVerde
estimado Calculado por el sistema con reglas IVA/PPM calculados, ETA sin confirmar Amarillo
manual Ingresado manualmente por el usuario Importaciones, egresos parametricos Azul
Regla de advertencia: si mas del 40% del flujo proyectado es estimado o manual, mostrar warning general indicando
baja confianza de la proyeccion.

8. Flujo de Onboarding — Cliente Nuevo
Paso Accion Responsable
1 Login en la app Cliente
2 Configurar parametros fiscales (tasa PPM obligatoria — bloquea sin esto) Kappo + Cliente
3 Configurar dias de pago (impuestos, remuneraciones, imposiciones) Kappo + Cliente
4 Conectar Kame API (client_id + client_secret) Kappo
5 Configurar escenario Make para facturas cobrar/pagar Kappo
6 Primera ejecucion Make — validar datos en Sheet y BD Kappo
7 Subir primer libro de remuneraciones Excel Cliente
8 Ingresar importaciones activas al modulo Cliente con guia Kappo
9 Generar primera proyeccion — etiquetar como v1 Kappo + Cliente
10 Revisar — explicar indice de confianza al cliente Kappo + Cliente
El setup inicial (pasos 2-10) es una hora de consultoria cobrable separada del mensual.
